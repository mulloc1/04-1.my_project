# Portfolio Website 평가 문항

## 평가 개요

| 항목  | 초점       | 평가 방식                             |
| ----- | ---------- | ------------------------------------- |
| **1** | 기능 동작  | UI·API·폼이 요구사항대로 동작하는지   |
| **2** | 코드 구조  | HTML/CSS/JS 분리와 파일 역할          |
| **3** | HTML·CSS   | 시맨틱 마크업, 변수, 레이아웃, 반응형 |
| **4** | JavaScript | 이벤트, 상태, API, 데이터 변환        |

---

## 항목 1 · 기능 동작

> 화면에서 직접 확인하거나, 동작을 설명·코드로 제시할 수 있어야 한다.

### 반응형 레이아웃

- **기준 1** ·  
  브라우저 창 크기를 줄였을 때 레이아웃이 모바일에 맞게 변경되는가?

### 테마 전환

- **기준 2** ·  
  테마 토글 버튼 클릭 시 다크/라이트 모드가 전환되고, 새로고침 후에도 선택이 유지되는가?

### 인터랙션 UI

- **기준 3** ·  
  햄버거 메뉴, 스크롤 애니메이션, 맨 위로 가기 버튼 등이 정상 동작하는가?

### GitHub API

- **기준 4** ·  
  GitHub API에서 데이터를 불러와 화면에 표시하고, 로딩·에러·빈 상태를 구분하여 보여주는가?

### 폼 유효성 검사

- **기준 5** ·  
  필수 입력값 누락, 이메일 형식 오류 시 즉각적인 피드백이 표시되는가?

---

## 항목 2 · 코드 구조

> 파일 분리 의도와 각 파일의 역할을 설명할 수 있어야 한다.

- **기준 6** ·  
  HTML, CSS, JavaScript가 각각의 파일로 분리되어 있고, 분리한 이유와 각 파일의 역할을 구분하여 설명할 수 있는가?

---

## 항목 3 · HTML·CSS

> 마크업·스타일 선택 근거와 레이아웃 방식을 비교하여 설명할 수 있어야 한다.

### 시맨틱 HTML

- **기준 7** ·  
  시맨틱 태그를 사용했고, 어떤 기준으로 태그를 선택했는지 설명할 수 있는가?

### CSS 변수

- **기준 8** ·  
  CSS 변수로 색상, 폰트 등을 정의했고, 변수로 관리하면 어떤 이점이 있는지 구체적으로 설명할 수 있는가?

### Flexbox · Grid

- **기준 13** ·  
  Flexbox와 Grid를 각각 어디에 적용했는지 확인하고, 해당 상황에서 그 방식을 선택한 이유를 비교하여 설명할 수 있는가?

### 반응형 전략

- **기준 15** ·  
  반응형 디자인에서 모바일 퍼스트로 작성한 이유를 설명할 수 있는가?

---

## 항목 4 · JavaScript

> 이벤트 처리, 상태 관리, API 호출, 데이터 변환 흐름을 코드와 함께 설명할 수 있어야 한다.

### 이벤트 등록 방식

- **기준 9** ·  
  `onclick` 인라인 속성 대신 `addEventListener`를 사용한 이유를 두 방식의 차이를 비교하여 설명할 수 있는가?

### 이벤트 → 상태 → 화면

- **기준 10** ·  
  이벤트 → 상태 변경 → 화면 업데이트 흐름이 코드에서 어떻게 이어지는지 따라가며 설명할 수 있는가?

### API 비동기 처리

- **기준 11** ·  
  `async`/`await`와 `try`/`catch`를 사용하여 API 호출 성공과 실패를 어떻게 분기 처리했는지 코드 흐름을 따라 설명할 수 있는가?

### 배열 메서드 · UI 변환

- **기준 12** ·
  배열 메서드를 활용하여 GitHub 데이터를 카드 UI로 변환하는 과정을 단계별로 정리할 수 있는가?

### 상태 객체

- **기준 14** ·
  상태 객체를 따로 만들어 관리한 이유는 무엇이며, 그냥 변수로 처리하면 안 되는지 설명할 수 있는가?
