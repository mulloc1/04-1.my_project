# 기준 15 · 반응형 전략 (모바일 퍼스트)

> **평가 항목:** 항목 3 · HTML·CSS  
> **질문:** 반응형 디자인에서 모바일 퍼스트로 작성한 이유를 설명할 수 있는가?

---

## 결론

**예.** 기본 스타일은 **모바일(좁은 화면)** 을 기준으로 `css/style.css`에 작성하고, `css/responsive.css`에서 `@media (min-width: ...)`로 큰 화면 스타일만 **추가**한다. 데스크톱 퍼스트(큰 화면 기본 + `max-width`로 제거)가 아닌 **모바일 퍼스트(작은 화면 기본 + `min-width`로 확장)** 전략이다.

---

## 모바일 퍼스트란?

```
모바일 퍼스트 (이 프로젝트)
  기본 CSS = 모바일
  @media (min-width: 768px) { /* 태블릿 이상에서 추가 */ }
  @media (min-width: 1024px) { /* 데스크톱 이상에서 추가 */ }

데스크톱 퍼스트 (사용하지 않음)
  기본 CSS = 데스크톱
  @media (max-width: 767px) { /* 모바일에서 덮어쓰기·제거 */ }
```

**핵심:** 작은 화면에 필요한 CSS만 기본으로 두고, 화면이 넓어질수록 **점진적으로 향상(Progressive Enhancement)** 한다.

---

## 이 프로젝트의 브레이크포인트

| 파일 | 역할 |
|------|------|
| `css/style.css` | 모든 화면 크기의 **기본** (= 모바일 우선) |
| `css/responsive.css` | 768px, 1024px **이상**에서만 적용되는 추가 규칙 |

```css
/* responsive.css — min-width만 사용 */
@media (min-width: 768px) { /* tablet */ }
@media (min-width: 1024px) { /* desktop */ }
```

`max-width` 미디어 쿼리는 **없다**.

---

## 모바일 기본 vs 데스크톱 추가 예시

### 네비게이션

| | 모바일 (기본) | 768px+ (추가) |
|---|-------------|--------------|
| 햄버거 | `display: flex` (표시) | `display: none` (숨김) |
| 메뉴 | `display: none` (숨김) | `display: flex; flex-direction: row` |
| 메뉴 열림 | `.nav__menu--open` 드롭다운 | (불필요 — 항상 표시) |

모바일에 **필수**인 햄버거·드롭다운이 기본이고, 넓은 화면에서 **가로 메뉴로 업그레이드**된다.

### About 섹션

| | 모바일 (기본) | 768px+ (추가) |
|---|-------------|--------------|
| 배치 | `flex-direction: column` | `flex-direction: row` |
| 이미지 | 전체 너비 | `width: 240px`, 옆에 배치 |

### 콘텐츠 너비

| | ~1023px | 1024px+ |
|---|---------|---------|
| 너비 | 뷰포트 전체 | `max-inline-size: 1100px`, 중앙 정렬 |

## 모바일 퍼스트를 선택한 이유

### 1. 실제 사용 비중

포트폴리오·랜딩 페이지는 **모바일 트래픽 비율이 높다**. 채용 담당자가 링크를 폰으로 여는 경우가 많다. 먼저 좁은 화면에서 읽기·탭하기 쉽게 만드는 것이 **사용자 경험 우선순위**에 맞다.

### 2. 점진적 향상 (Progressive Enhancement)

```
모바일: 읽을 수 있고, 탭할 수 있다 (최소 기능)
   ↓
태블릿: 가로 메뉴, 2열 About (편의 추가)
   ↓
데스크톱: 중앙 정렬, 큰 타이포 (시각적 여유)
```

기본이 동작하는 **최소 경험**을 보장한 뒤, 큰 화면에서만 "보너스" 레이아웃을 더한다.

데스크톱 퍼스트는 반대로 **큰 화면용 스타일을 미디어 쿼리로 제거·덮어쓰기**해야 해서 규칙이 `"display: none !important"`처럼 복잡해지기 쉽다.

### 3. CSS 복잡도·유지보수

**모바일 퍼스트:**

```css
.nav__menu { display: none; }           /* 기본: 숨김 */
@media (min-width: 768px) {
  .nav__menu { display: flex; }         /* 넓으면: 표시 */
}
```

**데스크톱 퍼스트 (가상):**

```css
.nav__menu { display: flex; }           /* 기본: 표시 */
@media (max-width: 767px) {
  .nav__menu { display: none; }         /* 좁으면: 숨김 */
  .nav__menu--open { display: flex; ... } /* + 드롭다운 규칙 */
}
```

모바일 퍼스트는 **추가**만 하므로 규칙 충돌이 적다. 이 프로젝트처럼 햄버거가 모바일 **기본 UX**인 경우 특히 자연스럽다.

### 4. 성능

작은 화면 사용자는 **데스크톱 전용 규칙을 파싱·적용하지 않는다**. `min-width` 쿼리 안의 CSS는 뷰포트가 조건을 만족할 때만 의미가 있다. (브라우저는 여전히 파일 전체를 다운로드하지만, 적용 우선순위·계산이 단순해진다.)

### 5. 이 프로젝트 맥락과의 일치

| 기능 | 모바일 기본 | 큰 화면 확장 |
|------|-----------|-------------|
| 햄버거 메뉴 | ✅ 기본 | 768px+ 제거 |
| 세로 Hero | ✅ 기본 | 여백·폰트 확대 |
| 1열 프로젝트 Grid | `auto-fit` | 열 수 자동 증가 |
| `viewport` 메타 | 필수 | 동일 |

햄버거·세로 스택·전체 너비가 **기본 스토리**이고, 가로 네비·중앙 정렬이 **나중에 더해지는** 흐름과 모바일 퍼스트가 정확히 맞는다.

---

## viewport 메타 태그와의 관계

```html
<meta name="viewport" content="width=device-width, initial-scale=1.0" />
```

모바일 퍼스트 CSS가 의도대로 보이려면 viewport 설정이 **전제**다. 없으면 모바일 브라우저가 ~980px 너비로 페이지를 렌더링해 미디어 쿼리가 엉뚱한 시점에 발동한다.

---

## Grid `auto-fit`과 모바일 퍼스트

```css
.projects-grid {
  grid-template-columns: repeat(auto-fit, minmax(280px, 1fr));
}
```

별도 미디어 쿼리 없이 **좁으면 1열, 넓으면多열**이 된다. 모바일 퍼스트 철학과 같은 **"기본은 좁은 화면, 넓어지면 자동 확장"** 패턴이다.
